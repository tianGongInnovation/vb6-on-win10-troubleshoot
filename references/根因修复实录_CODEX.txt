已经修好了，VB6 现在可以正常启动。下面是这次定位与处理的完整说明。

**结论与根因**
- 出错弹窗原文（用窗口枚举抓取，非猜测）：`'VB6EXT.OLB' 不能被加载。` 和 `未知的错误；退出`。
- 根因不在 VB6 文件本身：`VB6EXT.OLB`、`VB6.OLB` 文件完好，32 位类型库注册路径也正确，直接加载均成功。
- 真正元凶是注册表里的**应用兼容层**：`VB6.EXE` 被设置为 `~ RUNASADMIN WINXPSP3`，即“以管理员身份运行 + 以 Windows XP SP3 兼容模式运行”。
- 通过 A/B 实测确认：只保留 `WINXPSP3` 兼容模式 → 必弹上述错误；去掉后 → 正常进入“新建工程”窗口。所以是 Windows 的 XP SP3 兼容垫片干扰了 VB6 对 OLB 类型库的加载，属于这类“VB6 在 Win10 上装好却打不开”的典型情况，也解释了为什么**删除重装无效**——该设置存在 `HKCU` 兼容层里，卸载重装不会清除它。

**已做的修复与验证**
- 已执行修复，把兼容层改为仅 `~ RUNASADMIN`：
  ```
  reg add "HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers" /v "D:\Program Files (x86)\Microsoft Visual Studio\VB98\Vb6.exe" /t REG_SZ /d "~ RUNASADMIN" /f
  ```
- 已复查当前注册表值确认为 `~ RUNASADMIN`，且已实测启动 VB6，正常弹出“新建工程”窗口、无任何报错，随后已关闭、无残留进程。

**你现在只需做一件事**
- 直接双击 `D:\Program Files (x86)\Microsoft Visual Studio\VB98\VB6.EXE` 验证，应能正常进入 IDE。
- GUI 对照检查：右键该文件 → 属性 → “兼容性”页：**“以管理员身份运行”保持勾选**，“以兼容模式运行”**必须取消勾选**。
- 注意该设置是按登录账户保存的（HKCU）。如果你平时用其他账户启动 VB6，在那账户下同样改一次即可；如需要我可以给你一条命令直接改好。
